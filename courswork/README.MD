# Lane Detection & Steering Control System

Автоматическое определение полос дороги и управление рулевым управлением в реальном времени с использованием компьютерного зрения.

## 🎯 Основные возможности

### ✅ Базовая функциональность
- **Детекция полос дороги** — обнаружение сплошных и штрих-пунктирных линий разметки
- **Полиномиальная аппроксимация** — подгонка полиномов 2-го порядка к обнаруженным линиям
- **Адаптивное ROI** — автоматическое определение области дороги с использованием vanishing point
- **Расчет угла поворота** — определение необходимого рулевого действия
- **Визуализация в реальном времени** — отрисовка ROI, линий, рулевого колеса и статуса

### 🎯 Продвинутые функции
- **RANSAC для vanishing point** — устойчивое определение горизонта при сложных развязках
- **Механизм памяти линий** — сохранение и деградация линий при кратковременных сбоях (LANE_MEMORY_FRAMES=20, LANE_POLY_DECAY=0.98)
- **Адаптивная ширина полос** — запоминание ширины из предыдущих кадров для стабильности при потере одной линии
- **EMA сглаживание** — плавные переходы полиномов (EMA_POLY=0.30) и углов поворота (EMA_STEER=0.05)
- **Строгая фильтрация углов** — отбрасывание горизонтальных линий (|k| ∉ [0.5, 3.0]), которые вызывают прыжки руля
- **Анизотропная морфология** — прямоугольный kernel (15×3) вместо эллипса для полос на скоростной трассе
- **Отсечение letterbox артефактов** — исключение 2-3px рамки от искажений в концах трансформации

## 📊 Конфигурация

### Параметры процессинга (основные)

```python
# Размеры кадра
TARGET_SIZE = (1280, 720)   # (ширина, высота) целевого кадра
RESIZE_MODE = "fit"         # "fit" (letterbox с чёрными полосами) или "stretch"

# Обработка краев (Canny)
CANNY_LOW = 60              # нижний порог интенсивности градиента
CANNY_HIGH = 180            # верхний порог интенсивности градиента

# Детекция линий (Hough)
HOUGH_THRESH = 30           # порог голосов для детекции линии
HOUGH_MINLEN = 40           # минимальная длина линии (пиксели)
HOUGH_MAXGAP = 50           # максимальный разрыв внутри линии (пиксели)
```

### Параметры сглаживания и стабильности

```python
# EMA (Exponential Moving Average) для плавности
EMA_POLY = 0.30             # вес нового полинома (70% из памяти, 30% новое)
EMA_STEER = 0.05            # вес нового угла руля (95% из памяти, 5% новое — ОЧЕНЬ плавное)
RATE_LIMIT = 1.5            # максимальное изменение угла за один фрейм (град)
STEER_MAX = 25.0            # максимальный угол поворота руля (град)
```

### Параметры памяти линий

```python
LANE_MEMORY_FRAMES = 20     # макс. фреймов сохранения линии при отсутствии детекции
LANE_FADE_ALPHA = 0.3       # коэффициент прозрачности для линий из памяти
LANE_POLY_DECAY = 0.98      # деградация коэффициентов полинома (-2% в фрейм, умножение на 0.98)
```

### Параметры ROI (Region of Interest)

```python
SKY_CROP = 0.35             # исключить верхние 35% кадра (небо)
HOOD_CROP = 0.315           # исключить нижние 31.5% кадра (капот машины)
ROI_TOP_HALF_WIDTH_RATIO = 0.30  # ширина верхней части ROI трапеции (как доля ширины кадра)
BOTTOM_MARGIN_X_RATIO = 0.03    # отступ от края в нижней части ROI
LANE_YMIN_RATIO = 0.55      # начало отрисовки кривых линий (от высоты кадра)
```

### Параметры отрисовки руля

```python
WHEEL_ANCHOR = "lb"         # якорь (left/right + bottom/top: 'lb','rb','lt','rt')
WHEEL_OFFSET = (20, 20)     # смещение от якоря в пиксели (dx, dy)
WHEEL_SCALE = 0.60          # масштаб отображения руля (0.0-1.0)
TEXT_BOTTOM_OFFSET = 28     # расстояние текста статуса от нижнего края
```

## 🏗️ Архитектура

### Основные компоненты системы

#### 1️⃣ **compute_edges(frame)** — Обработка изображения
- Конвертация BGR → Grayscale
- Gaussian blur (5×5 kernel)
- Canny edge detection с L2 градиентом
- **Вычисляется один раз в цикле** и передаётся всем функциям (оптимизация -50% CPU)

#### 2️⃣ **detect_road_roi(image, edges)** — Адаптивное определение ROI
- Поиск горизонтальных линий горизонта через Hough
- **RANSAC для vanishing point** (100 итераций, threshold=40px)
- Взвешивание по длине отрезков (более длинные надёжнее)
- Автоматическое определение капота (горизонт в последних 5% кадра)
- Построение трапеции ROI с EMA сглаживанием (β=0.3)

#### 3️⃣ **detect_lines(frame, edges, poly, ymin, ymax)** — Детекция полос
- Отсечение 2-3px рамки letterbox (от артефактов)
- Анизотропная морфология: kernel (15×3) + MORPH_CLOSE (для штрихованных линий)
- Двойная маска: ROI полигон + Y-полоса (ymin:ymax)
- HoughLinesP в ограниченной области
- **Линии ищутся только внутри ROI** (не от края кадра)

#### 4️⃣ **fit_lane(lines)** — Подгонка полиномов
- Классификация: левые (k<0) / правые (k>0) по углу наклона
- Строгая фильтрация: 0.5 < |k| < 3.0 (исключает горизонтальные шумы)
- Удаление выбросов: keep точки в ±2.5σ от среднего X
- Валидация коллинеарности: y_std ≥ 1e-6
- Подавление RankWarning через np.errstate
- **Возвращает:** (left_poly, right_poly) или (None, None)

#### 5️⃣ **LaneTracker** — Отслеживание с памятью
```python
class LaneTracker:
    def __init__(self):
        self.poly = None              # Текущий полином
        self.frames_missing = 0       # Счётчик кадров без обнаружения
        self.lane_width = None        # Адаптивная ширина полосы из истории

    def update(p_new):
        # Если обнаружена → сохранить + обнулить счётчик
        # Если не обнаружена → деградировать (×0.98) + инкрементировать счётчик
        # Если >20 кадров → забыть полином (p=None)
```
- Механизм памяти: сохранение линий до LANE_MEMORY_FRAMES кадров
- Деградация: полином умножается на 0.98 каждый кадр без детекции
- Адаптивная ширина: запоминает вычисленную ширину полосы из фреймов, где обе линии видны

#### 6️⃣ **steering_from_lanes(poly_L, poly_R, w, h)** — Расчет угла руля
- **При обеих линиях:** центр полосы + сохранение computed_width
- **При потере левой:** смещение вправо на lane_width/2
- **При потере правой:** смещение влево на lane_width/2
- Расчёт ошибки позиции: e = (xc - x2) / w
- Расчёт угла: θ = arctan(Δx / Δy)
- Итоговая команда: steering = 40×e + 180×θ (в градусах)
- Итоговое ограничение: ±25°

#### 7️⃣ **draw_steering_wheel(frame, wheel_img, angle, anchor, offset, scale)**
- Масштабирование RGBA руля в соответствии с scale
- Позиционирование через якорь (lb/rb/lt/rt)
- Ротация руля на angle градусов
- **Premultiplied alpha compositing** для правильной прозрачности
- Отрисовка в соответствии с WHEEL_ANCHOR и WHEEL_OFFSET

## 🛡️ Применённые исправления уязвимостей

### 1. ❌ Двойной Canny → ✅ Единственный вызов
```
Вычисляем edges один раз в главном цикле и передаём везде
Экономия ~50% процессорного времени
```

### 2. ❌ Vanishing Point без RANSAC → ✅ Robust RANSAC
```
RANSAC с 100 итерациями + weighted by segment length
Устойчив к развязкам, бордюрам, шуму
```

### 3. ❌ Ширина полосы константа → ✅ Адаптивная
```
LaneTracker.lane_width запоминает computed_width из предыдущих кадров
Используется для восстановления второй полосы при потере
```

### 4. ❌ HUD попадает в ROI → ✅ Ограничение поиска капота
```
Горизонт капота ищется только в последних 5% кадра (y_hood_search_end=0.95*h)
Не ловим блики от дашборда
```

### 5. ❌ Letterbox артефакты в Hough → ✅ Отсечение границ
```
Обнуляем 2-3px по краям edges перед HoughLinesP
Не ловим резкую вертикальную границу canvas
```

### 6. ❌ Горизонтальные линии вызывают прыжки → ✅ Строгая фильтрация
```
Требуем |k| ∈ [0.5, 3.0] (крутые углы)
Исключаем почти горизонтальные артефакты
```

### 7. ❌ Залипание на смене полос → ✅ Деградация полинома
```
LANE_POLY_DECAY = 0.98: коэффициенты × 0.98 каждый кадр
Полином плавно вырождается к нулю за 30-40 кадров
```

### 8. ❌ Нестабильность при потере одной линии → ✅ Доверие видимой
```
Если видна одна линия → используем её + lane_width из памяти
Руль не прыгает хаотично при мигающей детекции
```

## 💡 Советы оптимизации

### Если видео обрабатывается медленно
1. Уменьшите `TARGET_SIZE` (например, до 960×540)
2. Увеличьте `HOUGH_THRESH` (детекция становится менее чувствительной, быстрее)
3. Используйте `RESIZE_MODE = "stretch"` вместо "fit"

### Если руль прыгает
1. Уменьшите `EMA_STEER` (например, до 0.02) — более плавное
2. Увеличьте `RATE_LIMIT` (например, до 2.0) — более консервативно

### Если полосы теряются на пунктирных линиях
1. Увеличьте `CANNY_HIGH` (например, до 200) — более строгое выделение
2. Увеличьте `HOUGH_MINLEN` (например, до 60) — более длинные линии

### Если в ROI попадает небо/HUD
1. Увеличьте `SKY_CROP` (например, до 0.40)
2. Уменьшите `HOOD_CROP` (например, до 0.25) — больше видно дороги

## 🐛 Известные ограничения

- **Ночная езда:** Canny требует хорошей освещённости; для ночи нужен другой фильтр (например, адаптивная контрастность)
- **Поворы на 90°:** Vanishing point может быть вне кадра; адаптация ROI нужна
- **Снег/дождь:** Морфология может не справиться с шумом; нужна предварительная фильтрация
- **Быстрые смены полос:** LANE_MEMORY_FRAMES=20 может быть недостаточно при очень быстрой смене
